# Авторизация и роли

## Публичный доступ

- Стример и остальные гости открывают публичную ленту без авторизации.
- Гость может искать, фильтровать и открывать одобренные видео на YouTube.
- Для отправки видео и голосования пользователь входит через Twitch OAuth.

## Пользователи и модераторы

- Twitch используется только как удостоверение личности пользователя.
- Сервер хранит неизменяемый Twitch ID, текущий ник и аватар.
- Основатель назначает роль `moderator` уже существующему пользователю по точному
  Twitch-нику. Перед назначением сервер получает и сохраняет Twitch ID.
- После следующего Twitch-входа сервер возвращает роль в сессии, и пункт
  «Модерация» появляется автоматически.
- Проверка роли выполняется на сервере для каждого защищённого API-запроса.

Рекомендуемый OAuth-поток: Authorization Code с `state`, серверным обменом кода и
короткой серверной сессией. Cookie сессии: `HttpOnly`, `Secure`, `SameSite=Lax`.
Twitch access token не передаётся frontend и не сохраняется в `localStorage`.

## Отдельный вход основателя

Основатель не обязан иметь Twitch-аккаунт. Для него используется отдельная,
не связанная с Twitch учётная запись:

1. Непубличный маршрут `/owner-access` без ссылки в интерфейсе.
2. Основной способ входа — WebAuthn/passkey.
3. При первом запуске passkey регистрируется по одноразовому bootstrap-токену,
   хеш которого задаётся на сервере и после регистрации уничтожается.
4. На случай потери устройства создаётся набор одноразовых recovery-кодов,
   хранящихся только в виде хешей.
5. Вход защищается rate limit, Turnstile, журналом попыток и уведомлением о новом
   устройстве.
6. В базе разрешена ровно одна активная роль `owner`; назначить второго
   основателя через интерфейс нельзя.

Скрытый URL — только дополнительное снижение шума, а не защита. Секрет владельца
нельзя хранить в JavaScript, `VITE_*` переменных или браузерном хранилище.

## Локальная проверка

В development доступен специальный URL `/?demo=1`. Только он показывает
переключатель ролей для QA. В production этот переключатель не собирается и
никак не влияет на серверные проверки ролей.
