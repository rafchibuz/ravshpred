# Проверка исправлений по диагностике 29.08–05.09.2026

Это локальный этап. Push в GitHub не означает разрешение на выкладку VPS.

## Автотесты

Из корня проекта:

```powershell
npm.cmd test
npm.cmd run build
docker compose -f deploy/compose.test.yaml up -d --wait
cd backend
$env:TEST_DATABASE_URL='postgres://test_runner:local-test-only@127.0.0.1:55433/ravshpred_test?sslmode=disable'
go test -count=1 ./...
go vet ./...
```

Тестовый PostgreSQL изолирован от базы сайта, без постоянного volume. Тесты создают и удаляют только собственные случайные схемы. Если TEST_DATABASE_URL не указан, интеграционные тесты **пропускаются**, а не подтверждают работу SQL.

Проверяется:

- повторный Twitch-вход создаёт аудит без конфликта UUID/text;
- смена категории создаёт аудит; ошибка аудита откатывает категорию и version;
- снимок сохраняет топ-100 и личное место за пределами сотни;
- новый экземпляр Store читает сохранённый снимок;
- неудачная публикация сохраняет предыдущий снимок целиком;
- гостю не возвращается чужое личное место;
- отсутствие первого снимка не запускает расчёт в HTTP-запросе;
- WebSocket отвечает на ping при занятом обработчике событий;
- HTTP-лог фиксирует фактический статус ответа.

## До разрешения выкладки

1. Прогнать интеграционные тесты на PostgreSQL 16.
2. На отдельной локальной копии истории проверить все каналы/периоды и совпадение баллов со старым расчётом. Сырые данные и секреты не коммитить.
3. Измерить p50/p95 выдачи готовых снимков, длительность каждого фонового расчёта, нагрузку на БД. Проверить одновременные чтения рейтинга, ленты и голосование. Цель для готового GET: p95 <500 мс, не гарантия до замера.
4. Проверить перезапуск API и сохранение выдачи; ошибку фонового обновления и выдачу старого результата.
5. Проверить в браузере переключение периода, собственное место, смену аккаунта, скрытую вкладку и мобильный экран.
6. Проверить сборщик на двух последовательных эфирах, обрыв сети и обновление токена. Очередь ограничена; при переполнении лог явно сообщает о возможном пропуске данных.

## Не завершено

- Сводные агрегаты по пользователю/эфиру: текущий фоновый worker ещё использует прежний расчёт по сообщениям. Он последователен и имеет отдельное соединение, но CPU/I/O PostgreSQL остаются общими. Нельзя обещать минутную свежесть, если полный проход длится дольше минуты.
- Подготовка всех первых снимков на большой истории и замеры ещё обязательны. При таймауте отсутствующий снимок останется «готовится», предыдущий сохранится.
- Пагинация предложки/профиля и расширенный нагрузочный сценарий — следующий этап.
- Проверка непрерывности и возможных пропусков истории сборщика требует БД/живого эфира.
