### Модерация

- Отдельная вкладка модерации.
- Одобрение и отказ; комментарий при отказе необязателен.
- Отметка «Отсмотрено».
- Удаление ролика так, чтобы он больше не появлялся ни в одном статусе/фильтре.
- На карточке модератора/владельца есть единая кнопка «Отсмотрено / удалить».
- Звуковое и визуальное уведомление владельцу/модератору при появлении нового ролика на рассмотрении.
  - Проверка очереди выполняется раз в 15 секунд.
  - Звук включается только после первого взаимодействия со страницей — это ограничение браузеров на автоматическое аудио.
  - При первой загрузке уже существующая очередь не озвучивается; сигнал появляется именно при новых поступлениях.

## Локальная разработка

Локальный `.env` содержит секреты и не коммитится. Для локального запуска URL должны указывать на локальный frontend:

```dotenv
APP_BASE_URL=http://localhost:8088
FRONTEND_URL=http://localhost:8088
TWITCH_REDIRECT_URL=http://localhost:8088/api/auth/twitch/callback
```

Запуск/пересборка:

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

Проверка:

```powershell
curl.exe --fail http://localhost:8088/health/ready
pnpm test
pnpm build
```

Если `.env` скопирован с сервера, перед локальным запуском нужно вернуть только три URL выше. Остальные секреты не менять. Если пароль PostgreSQL в новом `.env` отличается от пароля уже созданной локальной базы, его необходимо синхронизировать либо пересоздать только локальную тестовую БД с осознанной потерей локальных данных.

## VPS и развёртывание

- ОС: Ubuntu 20.04.6 LTS.
- Ресурсы: 2 GB RAM, 30 GB диск, дополнительно настроен swap 2 GB.
- Docker 26.1.3, Docker Compose v2.32.4.
- Проект: `/opt/ravshpred`.
- Доступ к GitHub: read-only deploy key.
- Приложение слушает только `127.0.0.1:8088`.
- Существующие VPN-контейнеры и Twitch-бот не должны изменяться при деплое сайта.
- TCP 443 занят Amnezia Xray, TCP 80 занят существующим Twitch-ботом.
- Публичный доступ сейчас работает через временный Cloudflare Quick Tunnel.

Серверный `.env` должен содержать публичный адрес в `APP_BASE_URL`, `FRONTEND_URL` и `TWITCH_REDIRECT_URL`. Нельзя копировать поверх него локальный `.env` с `localhost`.

### Обновление VPS после push

На VPS версия могла остаться на `e862321`; коммит `de3266a` со звуком и выравниванием карточек нужно подтянуть и пересобрать:

```bash
cd /opt/ravshpred
git pull --ff-only
docker compose --env-file .env -f deploy/compose.yaml up -d --build
curl --fail http://127.0.0.1:8088/health/ready
```

После этого проверить публичный `/health/ready`, Twitch-вход, отправку ролика и звук в открытой вкладке модератора.

## Временный публичный адрес

Сейчас использован Cloudflare Quick Tunnel. У него нет гарантированного срока работы или SLA. Адрес может измениться после пересоздания tunnel-контейнера. При смене адреса необходимо одновременно обновить:

1. Три публичных URL в серверном `.env`.
2. OAuth Redirect URL в настройках Twitch-приложения.
3. Контейнеры API/frontend.

Для постоянной публикации нужен собственный домен и Cloudflare Named Tunnel либо другая стабильная схема проксирования.

## Что осталось до полноценного продакшена

Следующий продуктовый этап:

1. Универсальный выбор при отправке: YouTube, TikTok, Instagram, Twitch-клип и «Другая ссылка».
2. Для «Другой ссылки» показывать просьбу сначала загрузить файл на файлообменник и прислать публичную ссылку; собственное хранилище файлов не делать.
3. Добавить страницу Twitch-клипов с периодами и сортировкой, затем список эфиров без обязательной подробной статистики.
4. Подключить автоматическую кинобазу только при наличии стабильного легального API; ручные данные должны оставаться запасным вариантом.

Приоритет 1 — безопасность и стабильный доступ:

1. Купить недорогой домен, настроить постоянный Cloudflare Named Tunnel и постоянный Twitch callback.
2. Ограничить и затем перевыпустить YouTube API key, потому что ключ ранее отправлялся в переписке.
3. Реально подключить Cloudflare Turnstile: переменные предусмотрены, но frontend/backend пока не проверяют challenge.
4. Добавить rate limiting и антиспам для OAuth, отправки видео, голосов и комментариев.
5. Настроить внешнюю копию бэкапов — S3-совместимое хранилище или другой сервер.
6. Настроить мониторинг доступности, оповещения и ротацию логов.

Приоритет 2 — эксплуатация VPS:

1. Перейти с root/password SSH на ключи, отдельного пользователя и отключить пароль только после проверки запасного доступа.
2. Учесть, что Ubuntu 20.04 вышла из стандартной поддержки. Подготовить безопасное обновление 20.04 → 22.04 → 24.04 или подключить ESM; перед этим сохранить конфигурацию VPN и проверить совместимость.
3. Настроить firewall осторожно: Docker, VPN и существующий бот уже используют порты.
4. Добавить безопасный deploy-скрипт: backup → pull → build → health check → понятный rollback.
5. Ввести нормальный механизм миграций БД для будущих изменений схемы.

Приоритет 3 — тестирование и юридическая часть:

1. E2E-тесты сценариев гостя, пользователя, модератора и владельца.
2. Проверка мобильных разрешений, разных браузеров, параллельных голосований и нагрузки.
3. Проверка защиты от XSS/CSRF, злоупотребления OAuth и повторных запросов.
4. Заполнить правила/политику/условия реальными контактами, доменом и сведениями оператора; перед публичным запуском желательно юридическое ревью.

## Быстрый smoke-test после каждого обновления

1. `/health/ready` возвращает `ready`.
2. Главная открывается гостю и по умолчанию показывает новые одобренные ролики.
3. Twitch OAuth возвращает пользователя на сайт с ником и аватаром.
4. Пользователь отправляет YouTube-ссылку; подтягиваются название, канал, превью и метрики.
5. В открытой вкладке модератора появляется toast и звучит сигнал нового ролика.
6. Модератор одобряет/отказывает, отмечает ролик отсмотренным и удаляет его.
7. Пользователь голосует только один раз выбранной реакцией и может изменить её.
8. Владелец создаёт новость; пользователь добавляет комментарий.
9. Создаётся свежий PostgreSQL backup и проходит проверку.

## Правила для следующего разработчика/задачи

- Не коммитить `.env`, токены, API keys, Twitch secret и пароли.
- Не перезаписывать серверный `.env` локальным.
- Не занимать порты 80, 443, 41095 и порты существующих сервисов VPS.
- Не удалять и не пересоздавать VPN-контейнеры или Twitch-бот.
- Перед изменением схемы БД делать backup.
- После логически завершённого этапа запускать тесты/build, коммитить и пушить в `master`, затем отдельно обновлять VPS.
